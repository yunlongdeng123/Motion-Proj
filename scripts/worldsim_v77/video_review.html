逐场景、逐帧同步看

每个场景三段视频，保留完整连续时序和六个相机。先看真实画面，再对照未编辑重建，最后检查目标平移后是否完整、稳定，以及周围背景受到了什么影响。

先这样看

  1. 在场景里选择一个相机；三列会同时切换。默认相机在第 20 帧能看到所选目标。
  2. 点“同步播放”，先用 1× 看整体，再用 0.5× 看车身边缘、路面和遮挡处是否闪动。
  3. 暂停后用“上一帧 / 下一帧”或拖动时间轴比对；可关掉标注，查看干净画面。
  4. 目标离开当前视角时，切“六路总览”找它，再选相应相机。框不出现不自动代表对象被删掉。

factual 在这里是什么意思？

同一时刻的六张真实相机图 → 冻结 VGGT-Ω → 反投影成三维点 → 沿原相机渲染。factual 不移动任何对象；第三列在同一份点场景上移动一个目标。两列使用完全相同的相机、尺度和渲染器。

每个时刻独立重建，没有时序平滑、补帧或生成补洞；这里检查的是当前逐帧管线的时序表现。它还不是一个跨时间持续维护的 4D 场景，也不是未见相机的新视角测试。

怎么理解黑洞、碎片和“移不干净”：深灰区域可能是没有重建到的表面、天空/80 米以外被过滤的区域，或点渲染留下的孔洞。第三列里移动后暴露出的地方不补全。目标由 GT 三维框内的点选取，所以可能漏掉车身，也可能带走路面；框标注只解释操作位置，不证明实例分离成功。
连续六相机 RGB → 逐时刻冻结 Ω → GT 标定 + 背景尺度 → 同一三维点场景 → factual / 目标平移 2m → 同相机、同帧对照

方法和这次视频的范围

项实际含义
时间使用全部现有 processed 图像，按 10 FPS 等间距播放。每一帧都来自相应时刻；原始相机精确 timestamp 未保留。视频无音轨。
GT 辅助用 GT 相机内外参；每帧通过 GT 框外背景 LiDAR 估计一个全局深度倍率。不是纯 RGB 的米制结果。倍率随帧变化也可能造成画面“呼吸”，因此将其纳入当前管线一起观察。
三维与渲染每帧六相机都参与 Ω 重建。仅保留有限值与 0.5–80m 深度的点，不按效果调 confidence；固定 3×3 点 splat、最近深度遮挡，无 mesh、补面或扩散精修。
基础编辑每场景固定一个已在前轮查看过的 GT track。把框内重建点整体平移 2m，yaw、尺寸、颜色不变；整段使用同一世界位移，不按画面重新选方向。其余点保持原样。
目标不再有 GT不猜测位置、也不延长轨迹；此时 edited 与 factual 一致。时间轴下方会明确显示。点数为零时同样不会伪造一个移动对象。
判断范围三个已曝光开发场景的人工复核材料。视频不是高保真通过声明；页面不代填人工结论，也不从当前三个目标推算全部对象的成功率。

每个视频是 2064×768 的六相机拼图（上排 0/1/2，下排 3/4/5）；相机按钮只同步裁切显示范围，不切换另一段内容。原视频缩放到每相机 688×384，与 Ω 输入和渲染尺寸对齐。MP4 使用 H.264，原始逐帧 PNG 保留在远端。
