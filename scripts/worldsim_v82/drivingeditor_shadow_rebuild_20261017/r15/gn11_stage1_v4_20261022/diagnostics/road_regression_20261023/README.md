## 影响范围与机制

以已导出的同次光栅道路贡献大于0.05作诊断域，两路输出使用完全相同的域：平均占全图20.53%，其中道路平均贡献52.03%；原V1的MAE 0.00652，合成后0.06065。该域由输出定义，只定位影响，不能冒充预注册道路GT mask。

实现中道路网格20cm，切向sigma=13cm，法向sigma=1.5cm；每点只有DC颜色和opacity。颜色目标只约束可靠来源投影中心的归一化道路颜色，覆盖目标推动独立道路alpha达到0.95；没有对最终合成的正常道路／车道线保持提供监督。R输出1919点的opacity中位数0.9123，42.57%的点超过0.95。

固定几何虽然排除了位置漂移和尺度增长，仍允许道路在最终真实深度排序中改变原有纹理和透射关系。下一节补充表明，单用DC平滑解释不完整：存在大面积整体变暗，而且V3道路同样使用DC。不能仅凭独立道路loss低或几何不动，判断合成质量合格。

## 继续追查：独立训练目标与最终联合输出不一致

输出端确实做了同次、真实深度排序的联合光栅化。`engine/utils/v4_road_render.py::render_composite`合并静态、动态和道路，并带有`@torch.no_grad()`用于输出；训练端`engine/utils/v4_road.py::RoadTraining.objective`仅调用`render_road`，不计算最终联合图损失。因此正常路面变暗、细节消失不会反馈给道路优化。独立参数更新可以保护V1训练路径，但不自动保护其最终合成结果。

对同次道路贡献>0.05且body_mask为0的固定诊断域做49帧逐帧均值：

| 证据 | 实测值 |
| --- | ---: |
| 每帧可靠来源中心采样 | 447.71个 |
| 每帧受影响非车身像素 | 30696.35个 |
| 独立道路在来源中心相对输入RGB的MAE | 0.00774 |
| 独立道路在整片诊断域相对GT的MAE | 0.04152 |
| 最终合成在同域相对GT的MAE | 0.06073 |
| GT／原V1／独立道路／合成平均亮度 | 0.35192／0.35155／0.36811／0.30433 |
| 合成比原V1和独立道路两者都暗至少1/255的像素比例 | 80.47% |

亮度Y=0.2126R+0.7152G+0.0722B。独立道路使用导出的归一化表面颜色；中心颜色通过原来源uv对应原生投影减0.5像素的位置做双线性采样。本表使用8-bit图像／量化贡献图，只是只读诊断，不冒充原始浮点训练目标。采样中心和整片域的分母不同，不能把两种MAE直接当作同域泛化比率。来源中心监督只检查稀疏投影位置，没有逐像素约束道路覆盖的整片区域。

道路单独平均更亮，联合后却明显更暗，说明合成损伤不只是平滑纹理；它还改变了原有高斯之间的透射／颜色累积。体渲染是逐深度累积`sum(T_i*alpha_i*c_i)`，新增高斯会同时削弱其后所有原高斯贡献，并非对两张独立成图做一次凸组合。原V1能用前后高斯的组合拟合正确颜色，在中间插入独立道路会打破这种组合。当前尚未对同R的具体前后高斯做原生贡献分解，不能据此把特定“黑色高斯”认定为全部原因。

V3的full正式重建PSNR34.6138、SSIM0.965538、LPIPS0.038921已从`r15_gn11_stage1_v3_serial_r1_20261021/final49/summary_r2/comparison.json`核对。V3的`scene/gaussian_model.py::get_features`同样把道路高阶SH清零，所以DC-only不是V4独有因素。V3在`v3_runtime_context.partition_state`对正常区域的真实联合图施加RGB／DSSIM，`base_loss.backward`可更新道路；位置、尺度、朝向也可调整。V4同时失去这些自由度和最终合成监督，不能当成只改联合监督的单因素消融，尚未分摊各因素的因果份额。旧浏览器V3显示图在raw102与其原生PNG有约0.00608 MAE的编码／派生差异，不能拿显示图复算值替代34.6138正式指标。

最小候选方案是V1仍走原训练路径，额外前向使用detach的V1参数与可导道路做真实联合渲染，只把可靠曝光区域的最终合成损失回传道路，并保留来源监督、固定几何。它不要求引回V3的车身梯度路由、动态深度替换等分层改动。此处仅提出候选，没有实现、重训或恢复RP。新审计脚本／49帧记录在运行诊断目录及本地交付的`objective_audit.json`；本轮零训练、零新GPU调用。
