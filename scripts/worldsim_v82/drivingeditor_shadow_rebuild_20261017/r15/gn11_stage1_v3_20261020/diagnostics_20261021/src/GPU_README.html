离线排查

  1. 直接打开index.html，选择四个实验和raw89—137。帧条每格是实际原生渲染，不插帧。默认raw102左侧残影，可切换前车残影和正常路面候选。
  2. 点击像素查看CUDA贡献Top20，可按Tα或颜色贡献排序；点击行联动真实协方差椭球、屏幕椭圆、永久道路ID及49帧来源。
  3. 下方显示实际执行的普通背景Top20移除前／后、全帧差异、道路贡献和区域外变化。预计算集合不等于当前复选集合，标签明确区分。
  4. 归因分支可选普通背景、道路、完整删除背景、联合与动态。原相机五分支、右移1m联合和full轨道视角是真实全模型原生图，不是点云截图。

实时GPU

运行 start_gpu.ps1，打开 http://127.0.0.1:8770/。需要原SSH别名 wm-vgpu-1011、远端可用空闲GPU。首次恢复模型与相机可能约一分钟；只按按钮启动工作进程。

点击“实时CUDA像素归因”，勾选Gaussian后点击“完整重渲染选中集合”；旋转／平移／缩放三维窗口后，可点击“渲染三维窗口当前视角”。点击三维“当前相机”再渲染可恢复原相机。所有诊断固定30K参数、raw时间和环境，只改变诊断掩码副本或相机。关闭启动器Ctrl+C释放本系统自己的SSH工作进程，不终止其他任务。

服务仅绑定127.0.0.1，固定四组、raw89—137、480×320和绑定SHA的ID，拒绝任意路径／命令、错误检查点、越界像素、非正交或镜像相机。全局GPU槽禁止与其他计算并发。无训练、无optimizer、不改原生依赖、不自动关机。

什么被验证，什么没有

CUDA诊断读取真实原生预处理与排序缓冲区，按同一alpha与提前终止表达式合成；每次对照原生RGB／alpha／depth／T，并独立使用one-hot通道核验Top20 ID的Tα。不是从高斯中心距离反推归因。中心z排序不等于椭球first-return，源谱系不是唯一Gaussian寿命ID。

反事实重新执行完整预处理、排序和光栅化，不从RGB减去颜色；远端保存原生浮点与哈希。移除造成图像变化是该固定渲染干预的因果影响，不等于重建更正确。21×21像素邻域外变化只作潜在误伤提示，没有自动取得正常区GT；跨帧同屏幕坐标不是同一世界表面。

新视角和遮挡后道路没有真实纹理GT，quality_accepted=false、human_verdict=null。三维总览仍是确定性采样几何；全模型外观必须看原生视角输出。来源可靠性和梯度不能证明因果质量。已清理的full／real_only旧checkpoint不能补造历史轨迹。

精度与文件

本地完整版密集显示alpha按1/65535、深度按1cm量化；便携ZIP密集热图4×4／8bit显示采样，法线代理关闭，未采样像素未知。49帧RGB、14034永久道路ID、60个CPU参考和新增CUDA查询数值仍保留。GPU浮点原件位于独立远端诊断目录，便携图像为显示副本。无原研究资产清理或修改。

源代码、CPU测试、GPU合同与数值验收、工程失败修复记录在source/，真实来源见gpu_receipt.json和view_receipt.json。遵守随包Graphdeco研究许可；这是项目诊断工具，不是官方“标准”软件。
