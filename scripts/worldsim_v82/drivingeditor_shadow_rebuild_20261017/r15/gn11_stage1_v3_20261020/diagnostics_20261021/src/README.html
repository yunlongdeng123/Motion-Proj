快速开始

  1. 直接打开 index.html：四组49帧、三维几何、LiDAR、BEV、全部49来源和48条内置CPU射线案例均可离线使用。使用新版Chrome／Edge。
  2. 要查询任意像素：在此目录运行 python server.py --port 8871 --remote-cpu，或运行 start_local.ps1。访问 http://127.0.0.1:8871/。此时需要用户本机配置好的 wm-vgpu-1011 SSH别名。只在点击查询时启动只读CPU worker，不使用GPU。
  3. 初次读取一个实验组的完整30K参数可能需几十秒；相同帧后续像素可复用投影。桥接器只允许固定四组、raw89—137和合法像素；不接受任意命令或路径。
  4. 切换实验组／逐帧时间轴。点击二维图选择像素；贡献表选择Gaussian联动椭球与屏幕3σ椭圆。三维窗口拖动旋转、Shift拖动平移、滚轮缩放；点击显示中心查看参数。
  5. BEV点击世界单元，下方显示其raw89—137同位置来源。切换六种证据模式，点击来源卡片切换相机。来源门限失败保持可见；少于2个来源不称为真实恢复。
  6. “保存诊断案例”与“导出GPU诊断请求”只下载JSON，不提交远端作业。选中的Gaussian保留checkpoint SHA与行号；GPU请求是待执行计划，不是验证凭据。

本版完成什么

这是3DGS重建研究常见的相机／几何／外观／残差／可见性查看器，另加入本项目道路证据与四组对照。既不是官方3DGS标准，也不是新算法结果。原始实现参考见主页面链接。

  • 原生R2已保存：RGB、分支、alpha、累积深度／期望z、稀疏LiDAR、道路在背景与联合透射率下的组贡献。
  • 派生预览：alpha按1/65535量化、深度按1cm量化（65535为无效，最大655.34m）、单位float16显示数据、道路来源8bit显示RGB。指标结论仍以原始浮点为准；CPU查询返回所选像素原始值。
  • 三维总览：确定性采样普通背景与动态；全部14034道路Gaussian保留。位置按原生SHM时间运动与有效opacity显示。DC颜色与点显示不是完整视角相关SH光栅化。
  • CPU全模型射线：读取全部Gaussian（非显示采样），遵循原生投影、协方差、负FOV、tile范围、alpha门限和早停规则，逐查询对照真实原生alpha／depth误差。CPU实现及相机重建存在浮点差异，未获CUDA逐ID核验；RGB参考不含EnvMap，不能宣称完整RGB重放通过。
  • Source lineage只是SGCM初始源组，不是唯一Gaussian寿命ID。普通背景的详细初始化／每步梯度／出生死亡历史若未保存，保持未知。

明确留待GPU

原生CUDA逐像素Top-K及累计T的完整RGB／alpha重放、普通背景去道路独立渲染、选中Gaussian集合实际移除后全帧重新光栅化、未选正常区域损伤检查、完整自由视角3DGS渲染。这些都尚未执行，不能以CPU参考或现成删除五车图代替。

不创建optimizer；不修改checkpoint、PCA、来源包或研究配置；不追加训练、调整损失或扩展199窗口；不代填human_verdict。四组原训练和正式评价已完成，但残影问题及科学质量并未因此通过。

可复现与故障记录

CPU导出代码、射线参考、测试和桥接服务位于source/；真实导出凭据见export_receipt.json，原资产清单与对照见data/。使用内存映射与50000行分块，兼容AutoDL无GPU容器2GiB内存。开发期两次普通checkpoint加载被容器OOM终止，无优化更新、无研究资产修改；随后修复为mmap并验证。最初mmap的Path兼容错误也保留于工程日志，不冒充成功。

关闭本地server.py会结束它自己启动的SSH CPU worker；不会终止训练或其他工作。远端适配器固定路径 /root/autodl-tmp/gsdiag_cpu_20261021_r1/，与冻结engine、原生CUDA依赖及campaign结果分离。主机没有被本工具关机或调整资源。

可调几何采样

静态（普通背景）和动态默认各取完整模型的2%，可调0—100%。道路始终全量保留。完整几何按块存于同目录，直接打开index.html即可调整0—100%基础采样、单车加密，无需localhost或AutoDL在线。默认只加载2%，调高时按需读取分块。

单独选择a5/a26/a18/a6/a37，单车默认10%，可提高到100%。默认按当前相机的原始单车掩码外扩5像素选取全部深度的中心，包含车后背景。加密同时作用于普通背景与动态，不能把这些中心当成已确认归属该车。

采样确定且随比例嵌套；提高比例不丢掉原有样本。数量分别显示抽样/全模型、本帧时间有效、当前画面内。颜色图例随分支/DC/尺度/opacity模式更新。点透明度可选真实有效opacity（无最低值抬升）或不透明中心（仅看分布）。点大小固定，真实覆盖与渲染贡献仍看二维原生结果和贡献表。单车区域已按49帧预导出；切帧时直接读取本地索引，速度取决于本机读取与绘制。

再次导出

AutoDL源码中的export_offline.py --output 诊断包目录会生成完整几何分块、49帧单车区域、默认2%样本和采样脚本。常规export_cpu.py已自动包含离线几何；在backend.ARMS登记新实验后，导出的scene.experiments自动生成实验选项。Windows的export_offline.ps1可一次完成已有包的远端CPU导出与下载更新。已有图像、原生归因和反事实证据保留；新实验使用对应检查点及原生渲染数据。

初始化、训练后与射线深度

直接打开原 index.html，无需启动本地服务。点击“三层对比”区域的“对比初始化与训练后”，会同时显示：初始化实际使用的49帧地面LiDAR（10厘米去重后的全量池）、初始化道路高斯、训练后道路及未创建网格的灰框。三层支持统一点大小和不透明显示；已有“当前帧LiDAR”保持独立。

初始化由冻结道路包和原 install_road_units 安装公式确定性复原，非伪造的step0检查点。点击初始／训练后道路点或灰框，可看世界坐标、位移、σ、不透明度、0.8米水平半径内支撑总数、原高度场使用的最近8点中有效数量及最近距离。白点显示附近支撑；紫色与黄色分别为初始与训练后1σ椭球。

粉色射线沿选中像素的中心，统一使用x+0.5、y+0.5；LiDAR、道路、普通背景各有独立距离标记。LiDAR从原始当前帧点云按同像素最近深度生成，避免旧投影图远点覆盖近点。道路使用已保存原生独立期望深度，普通背景使用全模型CPU参考光栅深度并核对原生背景合成；V1静态即普通背景，不存在专用道路。没有回波明确显示“无实测点”；没有分支覆盖不放深度点。期望深度不是椭球首交面。

Shift拖动沿屏幕方向平移；“框选统计”后拖动可比较投影区域内三层及缺失网格数量。框选是当前屏幕投影，不是三维体积。导出流程已自动加入这些数据；原模型与训练结果不改。完整导出需要远端g++和已有CPU环境。
