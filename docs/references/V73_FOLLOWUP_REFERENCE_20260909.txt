**我的判断是：下一阶段不应该继续把“增强后端解码器”当成默认唯一选项。应该开始检验“表面参数化”和“几何表示适配”这两个相互独立的问题；但也不应该因为结果不好，就同时换 DINOv3、换 DPT、解冻全网。**

还有一个值得先告诉你的事实：**DINOv3 官方论文已经做过“用 DINOv3 替换 VGGT 的 DINOv2 图像编码器”的实验，并在几何任务上取得改善。**但它沿用了 VGGT 的训练流程，包括对图像编码器进行几何任务微调，而不是把新编码器直接塞进旧 VGGT 权重后就获得收益。([arXiv][1])

因此，你现在提出的问题应该分成三个层次：

> **模型的哪个环节限制了当前任务？应该把监督送到哪里？最后得到的改善能支持多大范围的科研主张？**

---

# 一、先澄清：当前物理监督究竟进入 VGGT 的哪一层？

把当前系统拆开，比笼统说“基座＋后处理”更准确：

$$
I
\xrightarrow{E_{\theta_E}}
\text{图像特征}
\xrightarrow{A_{\theta_A}}
\text{跨视图几何特征}
\xrightarrow{D_{\theta_D}}
\text{深度与多尺度特征}
\xrightarrow{G_{\theta_G}}
\text{Actor 显式表面}
\xrightarrow{R}
\text{射线查询结果}
$$

这里：

| 层级                   | 负责什么                         | 当前 V7.3 状态 |
| -------------------- | ---------------------------- | ---------- |
| 图像编码器 \(E\)          | 从图像提取特征，原 VGGT 使用 DINOv2 初始化 | 冻结         |
| 跨视图聚合器 \(A\)         | 建立不同图像之间的几何联系                | 冻结         |
| 原生 DPT 解码器 \(D\)     | 将聚合特征解码为逐视图深度及中间特征           | 已训练        |
| Actor 查询与表面解码器 \(G\) | 生成规范坐标中的位置、法向和曲面片            | 已训练        |
| 物理读出 \(R\)           | 求实际表面交点、评价自由空间与返回            | 固定语义       |

当前报告明确：R10 训练了约 3265 万 DPT 参数和 167 万查询参数，只缓存冻结前缀，没有训练上层聚合器的 LoRA。

**因此，两句话要同时成立：**

**第一，你们已经不是“完全冻结 VGGT，只在结果外面做后处理”。**几何与自由空间损失已经作用到 VGGT 的原生 DPT。

**第二，你们还没有验证“让物理观测改变 VGGT 的跨视图几何表示”。**因为：

$$
\Delta\theta_E=0,\qquad \Delta\theta_A=0
$$

当前改变的是“怎样解码已有特征”，而不是“怎样形成跨视图特征”。

另外，**当前 R10、R12、R14 的首事件损失权重都是零**；先前 R9 的首事件实验是 LiDAR-only 路径。所以不能说，首事件监督已经在主联合模型中充分试过了。 

这就是下一步有必要检验上层表示适配的原因。

---

# 二、当前证据支持“查哪个环节”，但还没有证明“哪个环节有罪”

最新支持诊断显示，R10 的测量端点邻近覆盖为 **82.61%**，但正确沿束支持只有 **34.45%**，字面首交点正确率只有 **27.15%**。相对同监督 LiDAR 控制 R7，它的“表面邻近、却没有正确沿束交点”增加了 **12.95 个百分点**。

这足以说明：

> **现有生成结果的空间位置、方向、范围或连接关系，没有稳定满足真实射线观测。**

但不能直接推出：

> 一定是固定曲面片不好，而跨视图特征一定足够好。

错误的多视图特征也可能让解码器预测错误法向、错误位置；反过来，正确特征也可能被不合适的表面参数化解码坏。

所以我也需要修正前面的建议：**“下一步优先改表面参数化”是合理候选，不应被写成排他的结论。**

更合适的决策表是：

| 观察到的瓶颈                           | 优先改变什么            | 暂时不应据此改变什么   |
| -------------------------------- | ----------------- | ------------ |
| 深度和对应已经较准确，转换为曲面后交点明显变差          | 表面生成与转换方式         | 不先换图像编码器     |
| 输入特征能支持准确预测，但原生深度输出边界模糊、局部形状失真   | DPT 或其输出部分        | 不直接全量微调整个模型  |
| 同一 Actor 的多视图特征持续对应错误，解码器加大也难以改善 | 跨视图聚合器适配          | 不无限加深后端      |
| 小目标、弱纹理、夜间等条件下，图像特征本身缺乏可辨识性      | 图像编码器适配或更换        | 不把所有问题归因于曲面片 |
| 训练集改善、开发集持续退化                    | 数据覆盖、适配范围、正则和监督污染 | 不默认更多参数能解决   |
| 同一监督下，各种表示都朝错误方向优化               | 目标语义、对应关系和优化路径    | 不靠换基座掩盖问题    |

这是**定位层级**，不是要求你们把每个候选模块都跑一遍。

# 三、什么时候让自由空间／首事件监督进入跨视图几何表示？

## 1. 对当前项目：已经值得做，不必等后端路线“穷尽”

我建议在现有 R12/R14 对照收口之后，**保留一个当前最合理的表面解码器，增加一次上层跨视图聚合器的有限适配实验**。

原因不是“更端到端更高级”，而是当前存在一个尚未检验的限制：

> 后端被要求生成严格满足射线观测的表面，但它所依赖的跨视图表示，始终没有机会根据这些观测调整。

VGGT 原论文明确说明：跨帧关系主要在特征骨干中处理，DPT 头逐帧解码。**DPT 读取的是多视图特征，但它本身不重新建立跨视图对应关系。**([arXiv][2])

因此，假如问题在“不同视图把车体、背景、遮挡边界混在一起”，仅训练 DPT 与后端查询网络，未必是最直接的修复位置。

## 2. 我建议先适配哪里？

**优先考虑跨视图聚合器的上层，而不是立即解冻图像编码器的全部层。**

例如，在若干上层交替注意力模块中加入低秩适配（LoRA），让对应的帧内与全局交互有机会调整；保留 DPT 和表面解码器训练。具体层数和适配位置由结果决定，不预先写死。

这一步的研究问题是：

> **在同一个表面表示、同一组监督下，允许跨视图几何特征变化，能否改善正确沿束支持，而不是仅仅提高近邻覆盖？**

CAPA 已经表明，稀疏观测可以通过注意力中的参数高效适配改变几何输出；但它主要做样本级测试时适配，且其 VGGT 实验将适配参数放在图像编码器中。因此它能支持“表示层适配值得检验”，**不能直接证明“我们的上层聚合器就是根因”**。([arXiv][3])

## 3. 物理监督如何“进入表示”？

不必另造一个难解释的“几何特征物理损失”。

只要：

$$
L_{\mathrm{phys}}
\rightarrow
G
\rightarrow
D
\rightarrow
A_{\theta_A}
$$

这条反向路径成立，并且允许更新 \(\theta_A\)，物理观测就能影响表示。

但必须注意：

**有总梯度，不等于错误表面获得了有效物理梯度。**

例如，当首事件项对缺失表面只返回常数上限时，往上解冻更多层也不会凭空产生几何恢复信号；当前报告已经记录这种边界。

所以要保留直接几何恢复监督，不能期待“解冻＋首事件似然”自动解决全部问题。

## 4. 最有效的比较，是把两种变化分开

我建议围绕下面这个小矩阵组织后续探索：

|               | 冻结跨视图聚合器 | 上层聚合器有限适配 |
| ------------- | -------- | --------- |
| 当前较好的表面参数化    | 当前参照     | 检验表示适配    |
| 一种有针对性的新表面参数化 | 检验输出表示   | 必要时检验二者配合 |

不必立即完成四格。先补最有信息量的一格，再决定是否扩展。

它可以区分：

* 只有换表面参数化有效：瓶颈更靠近几何输出；
* 只有上层适配有效：冻结特征构成重要限制；
* 两者单独一般、联合有效：存在明显耦合；
* 两者都无效：应重新检查监督、信息量与数据条件。

**这比“连续失败后换一个更大的模型”更能推动科研收敛。**

# 四、什么时候考虑换 DPT？不要把两个“解码器”混为一谈

你们现在实际上有两套解码：

**DPT：**跨视图特征 → 逐视图深度。

**Actor 表面解码器：**深度、多尺度特征与 LiDAR → 可复用规范表面。

更换它们，解决的是不同问题。

## 1. 应该考虑替换或改造 DPT 的情况

**第一，错误在点图转换之前就已存在。**

例如，原生深度在车体轮廓处反复过度平滑，前后景之间出现错误深度过渡；或者不同视图对同一车体局部给出不一致的深度，而上游特征仍包含可利用的对应信息。

此时可以比较边界感知精化、不同的深度参数化，或更直接利用多层几何特征的解码方式。

**第二，任务输出与逐像素深度的表达方式不匹配。**

DPT 输出输入视图可见表面的深度，而你们最终要得到 Actor 全局规范表面。对未见侧面的生成、跨时刻共同表面和连接关系，不能要求 DPT 单独承担。

这时更合理的方案可能是：

> 保留 DPT 作为深度辅助任务，同时让 Actor 表面解码器直接读取聚合器的分层特征。

这样，三维表面就不必完全依赖“先生成点图，再从点图取种子”的窄通路。

**第三，DPT 的实现存在明显效率或输出伪影问题。**

这时可以采用成熟替代，而不必从头设计。VGGT-Ω 就保留低分辨率 DPT 卷积，把昂贵的高分辨率部分换成多层感知机与像素重排；作者也报告，完全去掉卷积虽然数值指标不错，却会产生可见的块状深度伪影。**这说明换头要看几何行为，不能只看结构是否更新、更轻。**([arXiv][4])

## 2. 当前不足以认定 DPT 失败

R11 训练后的开发命中率下降，说明**这套原生微调配置没有达到目标**；但其中同时包含共享参数适配、深度到规范坐标转换、离散支持选择和 PCA 曲面构造。它不是单独对 DPT 表达能力的检验。

因此现在不能用：

> R11 失败 → DPT 不适合 → 必须换头。

应该先判断：

> 深度本身坏了，还是深度变成物理表面的过程坏了？

# 五、什么时候考虑 DINOv3？现在可以做强基座比较，但不建议直接“换芯”

## 1. DINOv3 升级有真实依据，不只是追新

DINOv3 官方报告的 VGGT 实验使用 ViT-L 替换原 DINOv2 编码器，并沿用几何训练流程。为适配图像块尺寸从 14 到 16 的变化，主设置将输入从 \(518^2\) 调整到 \(592^2\)，还使用了四个中间层特征与相应训练调整。论文在相机位姿、多视图估计和视图匹配上报告了改善。([arXiv][1])

这足以说明：

> **DINOv3 是合理的升级候选。**

但不足以说明：

> **DINOv3 会自动解决你们的错误首交点。**

官方实验并没有检验当前这套动态 Actor 表面与自由空间任务。

## 2. “更换初始化”与“替换已训练编码器”不是一件事

从 DINOv3 初始化，再进行 VGGT 式几何训练，是完整的学习过程。

把现有 VGGT 中已与后续聚合器共同适配的编码器，直接替换为一个独立 DINOv3，则会改变特征分布、空间网格和下游接口。**即使输出维数相同，也不能认为表示语义兼容。**

因此，我更倾向于：

> **优先使用已经完成几何预训练的 DINOv3 系模型作为新基座，而不是自己拼接“DINOv3＋旧 VGGT 后半部分”。**

VGGT-Ω 已采用 DINOv3 初始化的图像编码器，并在几何训练中更新它；它同时改变了聚合和预测头，并不是纯粹的编码器替换。([arXiv][4])

**对于你们，VGGT-Ω 这样的完整基座比较，比单独换 DINOv3 更适合先做。**但结果只能解释为“新几何基座整体带来的变化”，不能全部归功于 DINOv3。

## 3. 什么证据会让我正式建议替换图像编码器？

我会看三个条件。

**图像特征层面存在稳定短板。**例如，在可靠对应处，当前编码器对车体边界、重复纹理、弱光或小目标的特征定位持续落后，而 DINOv3 在相同数据条件下有实际改善。

**后端已经不是主要限制。**若换一个合理表面解码器后问题依旧，而且不同解码器都受同类图像条件影响，更值得向前端寻找原因。

**新基座确实改善最终任务。**不是只展示更漂亮的特征相似度图，而是改善独立日志中的正确支持、命中率和自由空间表现。

反过来，若最新基座加简单融合已经解决了原先的问题，你们应接受这个事实。后续贡献就需要建立在它之上，而不是继续证明旧基座需要复杂修补。

# 六、什么时候考虑全量微调？

**全量微调不应该成为“最后绝望时才允许尝试”的路线，也不应该成为“局部微调不行就必然更强”的路线。**

我建议区分两种用途。

## 1. 作为瓶颈诊断：可以较早做

当你们已有一套语义可信的监督和可运行的几何输出后，可以在开发研究中加入一次**范围更大的联合微调对照**。

它回答的是：

> 当前适配范围是否限制了这个任务的可学习性？

不必等每一种 Query、每一种样条、每个损失权重都试完。

但不能把全量微调称为“性能上界”。虽然可训练参数范围更大，实际优化和泛化可能更差。

## 2. 作为主路线：需要更强理由

我会在下面这些条件同时逐步出现时，提高全量微调的优先级：

| 条件                          | 意义                          |
| --------------------------- | --------------------------- |
| 扩大上层适配范围，在训练和开发集都持续改善       | 说明冻结范围可能确实过窄                |
| 合理的局部适配仍有可重复的拟合瓶颈           | 不只是“开发集不好”，而是当前参数空间难以表达所需变化 |
| 标签、时空对应和自由空间定义较可信           | 避免把错误监督传播到整个模型              |
| 训练数据覆盖足以支撑目标场景，而非少数重复 Actor | 降低模型记忆特定场景的风险               |
| 全量微调相对普通微调、PEFT 有明确增量       | 证明额外自由度值得使用                 |

**当前 R11“训练拟合改善、开发集退化”，不是一个支持直接扩大解冻范围的正证据。**它更需要区分监督污染、参数漂移和分布覆盖。

已有迁移学习研究也表明，全量微调可能改善分布内表现，却损伤分布外性能；但这些结论来自其特定实验与理论设置，不能直接预言你们的结果。([arXiv][5])

## 3. 全量微调时，什么应保持不变？

已知标定和 Actor 轨迹仍应作为真实几何依据，不能让网络通过修改这些已知量来“解释掉”错误表面。

对于模型本身，建议保留可靠的深度／对应辅助监督，并考虑较小的预训练层更新幅度。若使用原模型蒸馏，也不能对明显错误的几何盲目保持一致。

另外，你们目前实际训练主要来自 **20 个独立日志、371 个有输入的训练 Actor**。更多全轨迹点能增加观测，但不等于相同数量的新场景。这个事实应影响全量微调的证据要求，**不是用来设定“只能用 3090”的资源上限**。

资源允许时，可以使用更大显存或多卡保留输入规模。决定是否全量微调的核心，应是**能否学到可泛化的变化**。

# 七、科研上，怎么证明“这种改进有必要”？

这里必须区分三件事：

> **某种几何约束有必要；你设计的损失有效；你选择的架构有必要。**

它们不能互相替代。

## 1. 可以证明：单向覆盖不足以约束正确表面

你们当前的覆盖项，本质上包含：

$$
L_{\mathrm{cov}}(S)
=
\frac1N\sum_i \operatorname{dist}(x_i^*,S)
$$

向表面集合加入任意额外几何 \(A\)，就有：

$$
L_{\mathrm{cov}}(S\cup A)
\leq
L_{\mathrm{cov}}(S)
$$

这是直接由“最近距离取最小值”得到的。

也就是说：

> **增加错误前表面，完全可能不伤害、甚至改善这个覆盖项。**

这解释了为什么需要某种补充约束或合适的表示先验。

但它**没有证明**你们的有限宽束损失、边界采样、Query 或 PEFT 是唯一必要的办法。其他方法可能通过不同监督、不同表示或融合方式解决同一问题。

论文需要证明的是：

> **在同样信息、合理训练和强对照下，我们的具体方法更有效，而不只是指出现有指标不充分。**

## 2. 还需要纠正一个潜在的大叙事

不能写成：

> “VGGT 原来不知道首次可见表面，我们第一次把首交点概念引入几何学习。”

VGGT 原论文对深度的定义，本来就是投影到该像素的场景点中最小的深度，并进行深度监督。([arXiv][2])

你们真正研究的缺口更具体：

> **输入视图的深度预测，经过跨时刻融合与表面补全后，是否仍能形成对新射线有效、与独立传感器观测一致的可复用表面。**

这比“视觉模型缺物理概念”准确，也更容易设计有说服力的实验。

## 3. 必要性需要“替代方案竞争”

最终至少要排除三种解释：

**只是多了真实 LiDAR。**用相同 LiDAR 的简单对齐、融合和 LiDAR-only 控制排除。

**只是多了训练自由度。**用同层位的普通几何微调、普通 LoRA 或充分训练的原生头排除。

**只是适配了你们自己的读出器。**用固定的独立表面查询方式，以及另一项不依赖当前损失定义的应用评价排除。

尤其是最后一点：若方法只在自己设计的软读出上提高，换成统一硬交点就失效，不能称为几何改善。

---

# 八、是不是必须“各种任务都有用”才能成为好论文？

**不需要。任务专用性不是缺陷；证据范围与主张范围不匹配才是缺陷。**

你们可以选择不同层级的论文定位：

| 想主张什么                | 需要什么证据                     |
| -------------------- | -------------------------- |
| 改善动态 Actor 的传感器观测一致性 | 清晰主任务、强同信息基线、独立日志结果        |
| 学到可复用的三维表面           | 同一表面在新视点、新时刻及另一类几何查询中仍有收益  |
| 方法适用于多种几何基座          | 多个基座分别按同一原则适配后有增量          |
| 改善通用几何表示             | 适配后的特征被冻结，用相同下游头在其他任务上验证迁移 |
| 对一般视觉任务普遍有效          | 广泛任务与数据证据；当前没有理由追求这个主张     |

## 1. 跨数据集，不等于跨任务

在 nuScenes 训练，在 AV2 上首交点更准，证明的是跨域泛化。

换两个激光雷达、换扫描密度、换查询视角，也主要是同一任务内的鲁棒性。

这些都重要，但不能写成“通用视觉表示改善”。

## 2. 最适合你们的第二项任务：同一表面的新视点可见性

我更推荐：

> **冻结已经重建好的 Actor 表面，评价新相机视点下的深度或前景遮挡关系。**

模型不再针对第二项任务重新训练，也不用当前首事件概率头，而是直接用同一表面进行固定查询。

这样可以问：

> 在 LiDAR 观测下学到的几何修正，是否改善了另一组观察方向与成像方式？

不过必须有可信的新视点深度、遮挡或轮廓真值。**仅把同一批 LiDAR 点投影成图像再计算一次，不足以形成强的独立跨任务证据。**

碰撞正确性可以作为更远的应用，但需要独立碰撞几何真值。正确首交点并不自动保证完整内部结构和碰撞边界。

## 3. 若要主张“几何 representation 改善”，需要额外做特征迁移

比较适配前后的特征：

$$
z_{\mathrm{before}}
\quad\text{与}\quad
z_{\mathrm{after}}
$$

将它们冻结，在另一份数据上训练**相同容量、相同预算的下游头**，例如用于对应匹配、深度或法向估计。

重要的是切断原任务的特殊读出：

> 不让你的首事件头负责解释所有收益。

而且，要明确你改善的是哪一级特征。若只训练 DPT，不能声称冻结的聚合器表示得到了改善；若适配了聚合器，才有资格检验其表示迁移。

LoRA3D 在重建、位姿估计和新视点渲染上评估适配效果，是“跨几何用途验证”的一个先例，但它不等于证明所有视觉任务都会受益。([arXiv][6])

## 4. 你们最合理的泛化目标不是“所有视觉任务”

我建议当前瞄准：

> **对表面位置、可见性和射线交点敏感的一组几何任务。**

图像分类、语义识别未必需要厘米级表面修正；一个专门修正几何的训练过程也未必改善它们。

不需要为了“泛化性”去扩展分类、分割、VLA、规划和强化学习，最后又回到大而全。

# 九、我给 V7.3 的下一步排序

**当前主线仍然保留，但不再把所有希望都压在后端曲面片上。**

### 第一，完成当前物理目标对照，再同时考虑两个瓶颈

以 R12/R14 的结果为参照，区分：

> 错误表面是否获得了更合适的约束；正确沿束支持是否真正增加。

随后允许“一个新表面参数化”与“上层聚合器有限适配”分别进入比较，不要求前者被完全穷尽以后才能做后者。

### 第二，把新的完整几何基座纳入参照，而不是立即自行换编码器

DINOv3 已有明确的几何迁移依据，VGGT-Ω 也已经采用它。应检验新基座加简单适配后的水平，再决定继续以原 VGGT 做主载体是否合理。

**新基座可以现在开始作为对照考虑，但更换主载体必须由本任务结果决定。**

### 第三，全量微调作为受控诊断，而不是信仰或禁区

若有限适配暴露出明确的表示瓶颈，可以较早做全量微调试验；若只是训练拟合越来越好、开发越来越差，就优先处理泛化问题。

### 第四，先建立一个主任务正结果，再扩展一项真正不同的几何用途

你们现在最缺的仍是稳定的主任务增量，而不是再增加四项应用。跨任务验证应围绕**同一表面或同一表示的复用**，而不是为每个任务重新训练一整套系统。

---

**最终建议可以概括为：**

> **让监督进入哪里，由错误发生在哪一层决定；换什么基座，由真实任务比较决定；论文能说多广，由独立迁移证据决定。**

对当前 V7.3，我最推荐的转变是：

**从“冻结前缀，持续增强后端”转为“表面生成与上层几何表示联合适配的可检验路线”。**DINOv3／VGGT-Ω 是值得引入的强基座参照，全量微调是可以使用的诊断工具；但这三者都不能替代对监督语义、几何支持和独立泛化的验证。
