# 研究资产保留与复现

适用：用户 2026-09-22 授权清理 `/root/autodl-tmp`；已经有验证结论的实验不要求全部大型 artifact 常驻，只要保留可执行复现入口。执行状态只见 [RESEARCH_STATUS](RESEARCH_STATUS.md)。

- 必须保留：源码版本与入口、冻结配置和 seed、原始输入或已确认可用的来源、关键模型/训练 checkpoint、输入角色、完整指标与失败结论。好案例和否定结论同样保留。
- 已收口实验的大型派生视频数组、可重建条件和特征缓存可清理。先核实恢复依赖和当前占用，再保存逐文件路径、用途、大小、恢复命令及清理结果。只保留文档链接而缺失恢复依赖，不算可复现。
- 稀疏条件优先无损压缩；压缩流与原件逐字节一致后才移除原件。既有脚本若要求 `.npy`，先按需恢复。
- 生成输出可在保留模型、输入、embedding、seed及代码的情况下重新生成。压缩审阅视频不替代原始数组的精确指标。完整闭环重跑与保存条件回放要明确区分。
- 不因清理整批删除版本目录，不删除结论/协议/参数来省空间。新的复现写新输出目录，不覆盖旧实验终态或把复现计为独立确认。
- 包下载缓存可清理；安装环境和权重需核对后另行处理。避免为了省下载缓存破坏安装环境的符号链接或源码依赖。

逐文件记录、依赖核验与恢复方法：[2026-09-22 第一轮：V7.5](autoresearch/storage_cleanup_20260922/README.md)、[第二轮：V4 数据与早期 runs](autoresearch/storage_cleanup_20260922_r2/README.md)。完全相同的冻结副本可在逐字节核验后共享存储并保留原路径；从保留的公共原包展开的数据可按可用原包、逐文件来源清单与已测试恢复入口清理。复现写新目录；修改共享资产前先复制成独立文件。

用户随后明确要求整体撤下 V4 数据：执行范围与恢复代价见 [V4 数据退休说明](autoresearch/v4_data_retirement_20260922/README.md)。旧版本被引用不再自动构成常驻数据的理由；保留来源、配置和结论，接受下次重跑前重新准备输入。
