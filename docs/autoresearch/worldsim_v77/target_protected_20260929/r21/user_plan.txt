**建议把本轮定义为：Temporal reveal 数据 + 带身份、几何和可信度的 projected actor-state condition。**目标是让模型同时回答：

- **这里有车：是哪辆车、哪些部分有观测依据？**
- **这里没有车：有哪些真实背景证据支持？**
- **这里信息不足：不能把未知当成空背景。**

你提出的 2D Gaussian surfels 可以作为条件表示，但建议先验证条件本身的价值，再加入完整 surfel 表示。下面是结合论文和当前代码制定的计划，属于新方案，尚未启动实施。

**一、相关工作支持哪些部分**

| 工作 | 可以借鉴的部分 | 不能直接据此保证的事情 |
|---|---|---|
| [2DGS](https://surfsplatting.github.io/) | 用嵌入三维空间的二维高斯面片表示表面，进行可微投影 | 不自动解决动态 actor 追踪、身份保持和隐藏表面恢复 |
| [Street Gaussians](https://zju3dv.github.io/street_gaussians/) | 将车辆表示放在各自局部坐标系，通过轨迹与背景组合 | 使用的是 3DGS；完整场景重建结果不能直接当成当前 DELETE 的合法输入 |
| [Feature 3DGS](https://github.com/ShijieZhou-UCLA/feature-3dgs) | 将图像特征附着在 Gaussian 上并渲染特征图 | 高维特征渲染需要专门支持，不能直接等同于普通 RGB rasterizer |
| [WoVoGen](https://arxiv.org/html/2312.02934v2) | 将三维世界特征投影成二维条件，并通过条件分支、局部 attention 引导生成 | 它支持空间控制，但没有证明能恢复我们指定的同一辆隐藏后车 |
| [DriveEditor](https://yvanliang.github.io/DriveEditor/) | 已有位置、外观、三维特征的不同注入路径 | 当前 DELETE 分支关闭了有效物体条件，需要明确改造 |

因此，这个方案有相关工作支撑；**“Temporal reveal + 指定保护车身份 + 删除后的可见性条件”如何组合并带来真实 DELETE 收益，仍是需要验证的研究命题。**

**二、整体结构**

```mermaid
flowchart LR
    X[带洞视频与删除 mask] --> D[DriveEditor]
    X --> O[提取合法可见证据]
    O --> A[Actor 状态<br/>身份、表面、轨迹、可信度]
    A --> R[移除目标 A<br/>投影保留的 actors]
    O --> B[真实背景证据]
    R --> C[特征、深度、可见性<br/>有车、空背景、未知]
    B --> C
    C --> P[空间条件与身份 Adapter]
    P --> D
    D --> W[局部写回]
    W --> V[DELETE 视频审核]
    Y[真实原视频 Y] -.仅作训练监督.-> D
```

这里有一条必须坚持的边界：**训练时，构建 actor 状态的输入也必须经过遮挡。不能先从完整 GT 视频重建 B，再把 B 被遮住的部分作为条件交给模型。**否则合成任务会变容易，真实删除时却拿不到同样的信息。

离线视频编辑可以使用前后帧，但必须提前固定可用窗口，训练和真实推理遵守同一规则。

**三、修改 actor-state 定义**

建议将 actor 状态写为：

\[
A_i=\{S_i,e_i,T_i(t),r_i,q_i\}
\]

其中：

- \(S_i\)：actor 局部坐标系中的表面表示；
- \(e_i\)：从该 actor 可见部分提取的身份与外观特征；
- \(T_i(t)\)：逐时刻位姿；
- \(r_i\)：删除目标或保留对象；
- \(q_i\)：观测、追踪和几何可信度。

本轮是离线恢复，已有 \(T_i(t)\) 时，速度可以从轨迹导出。**加速度先不作为独立条件**，避免引入噪声和状态不一致。

你的 surfel 定义基本合理，但还需要 opacity，并处理 normal、切平面与 rotation 的冗余。可以简化为：

\[
S_{ij}=
\{\mu_{ij},R_{ij},s_{u,ij},s_{v,ij},
\alpha_{ij},f_{ij},q_{ij}\}
\]

\(R\) 的前两列确定切平面，第三列确定法向；两个尺度确定面内协方差。

第一版中：

- 几何和位姿先冻结；
- \(f_{ij}\) 来自合法可见图像特征，经共享投影网络转换；
- 不给每辆车分配可以通过隐藏 GT 任意优化的自由 embedding；
- 保留局部纹理信息，不能只用一个“car”类别向量代表身份。

**四、投影输出需要比 \(F,D,V\) 多两类信息**

建议输出：

\[
C_t=\{F_t,D_t,V_t,O_t,N_t,U_t,Q_t\}
\]

| 条件 | 含义 |
|---|---|
| \(F_t\) | 对应 actor 的局部外观特征 |
| \(D_t\) | 深度及有效范围 |
| \(V_t\) | **删除目标之后**的可见性 |
| \(O_t\) | 有观测支持的保留车辆区域 |
| \(N_t\) | 有真实证据支持的无车背景区域 |
| \(U_t\) | 未知或证据冲突区域 |
| \(Q_t\) | 条件可信度 |

两点尤其重要。

**删除 A 后，要重新计算 B 的可见性。**如果仍使用原场景的遮挡结果，B 会继续被 A 挡住，条件恰好无法支持需要恢复的位置。

**没有 surfel 投影，不等于这里没有车。**它也可能表示从未观测到、重建失败或跟踪丢失。因此不能直接设置：

\[
N_t=1-O_t
\]

\(N_t\) 必须由输入中真实看到过的道路、墙、草地等证据支持；证据不足的地方进入 \(U_t\)。训练 GT 可以用于监督和评价，却不能直接生成推理时没有的“正确空背景条件”。

多个 actor 的特征也不能简单平均。需要保留各自身份，并按深度、可见性和投影范围分配，防止把两辆车融合成一辆。

**五、本轮数据以 Temporal reveal 为主**

建议先做 **50 条完整流程样本**检查工厂，再扩到约 **300–500 条训练片段**，分散到至少 30 个场景。另留场景隔离的合成验证集；背景来源和 mask 来源都不能跨训练、验证复用。

首轮固定配比：

| 类型 | 比例 | 主要目的 |
|---|---:|---|
| Temporal protected-actor reveal | **60%** | 恢复同一辆 B，覆盖单车、双车、扫过和触边 |
| 密集交通中的已知无车背景 | **25%** | 抑制新增幻觉车 |
| 普通背景恢复 | **15%** | 保留道路、栏杆等基础补景能力 |

这些比例是首轮实验配置，不是已验证的最优比例。

每个 reveal 样本必须记录：

- 遮挡比例随时间的曲线；
- 当前被遮表面，在其他输入帧中真实可见的比例；
- 可见证据距离当前帧多远；
- 一个还是多个保护 actor；
- 几何对应的可信度。

**主评测先聚焦“有充分证据却恢复失败”。**只见过车尾、要恢复从未出现的车头，应该单列为信息不足组。

窗口目标为 **2–3 秒连续曝光**。当前模型入口只有约一秒，必须先验证 20／30 帧训练与推理，确保显露证据进入同一次模型调用。显存不够时统一采用两秒窗口，并让所有对照使用相同长度；不能将三秒拆开后仍声称模型使用了三秒证据。

**六、条件接入分两级，避免一次引入过多变量**

第一阶段先实现较简单的 projected actor-state：

- 轨迹与深度投影；
- 有车／已知背景／未知区域；
- 从可见 crop 提取的身份特征；
- 按投影区域约束身份 attention。

空间条件走一个轻量、多尺度 residual adapter；身份特征走独立的、受投影范围约束的 cross-attention 分支。可以借鉴 [ControlNet 的零初始化连接](https://arxiv.org/abs/2302.05543)和 [IP-Adapter 的独立图像条件分支](https://ip-adapter.github.io/)，但需要适配 DriveEditor。

保留原骨干和原有输入通道，新增条件支路。**这属于条件接口扩展，不能再称 architecture 完全不变。**

还要处理两个已经查到的接入问题：

- DriveEditor 的 DELETE 分支会将原物体外观条件替换为空条件，保护车不能直接塞进原字段就期待生效。[官方实现](https://raw.githubusercontent.com/yvanliang/DriveEditor/main/sgm/modules/diffusionmodules/video_model.py)
- 官方 2DGS rasterizer 默认是 3 通道 RGB，高维 \(F_i\) 需要另做适配和正确性验证。[官方配置](https://raw.githubusercontent.com/hbb1/diff-surfel-rasterization/main/cuda_rasterizer/config.h)

第二阶段再加入 surfel 局部特征投影，与第一阶段比较。**2DGS 的价值要体现在更准确的局部对应、遮挡和身份恢复上。**如果简单条件已经足够，没必要立即增加逐 actor 重建与高维渲染成本。

**七、实验按增量推进**

保留原模型和有效 r7 作为固定参考。新增实验统一初始化、时间窗口、分辨率、训练预算和采样规则：

| 对照 | 数据 | 新条件 | 回答的问题 |
|---|---|---|---|
| A | 新 Temporal reveal 配方 | 无 | 现有网络使用更合适数据能改善多少 |
| B | 同 A | 几何＋有车／背景／未知 | 空间与存在状态是否有用 |
| C | 同 A | B＋身份特征 | 能否恢复指定 B，而不只是生成一辆车 |
| D | 同 A | C 的局部特征改用 surfel 投影 | 2DGS 是否带来额外收益 |

D 在 C 的接口和收益得到验证后再做，不同时铺开全部实验。

第一轮保持相同损失设置，分别记录洞内车辆和背景区域的误差；暂不同时引入多种新损失。若后续需要身份损失或区域加权，再单独做对照。

另加少量诊断检查：

- 关闭 adapter 时能否恢复基础输出；
- 更换身份特征后，对应车辆外观是否响应；
- 去掉真实显露帧后，恢复是否变差；
- 条件不确定时，是否错误地把保护车抹成道路。

这些检查用于确认模型确实利用了条件，不用于制造效果排名。

**八、先修入口，再按实体任务验收**

最新诊断已经确认 A022 有车头边缘漏在 mask 外。因此正式对照前先完成：

- 目标完整覆盖与写回检查；
- 重复任务去重；
- 初始化精度修复；
- 空 mask 帧和长窗支持；
- 条件读取隐藏 GT 的隔离检查。

旧视频保留，新入口对所有权重统一重跑，避免把入口修复算成模型收益。

本轮验收必须同时覆盖两侧：

| 应有车辆 | 应无车辆 |
|---|---|
| 身份、数量、结构正确 | 不新增车辆或车形残留 |
| 双车不融合 | 道路和栏杆结构保留 |
| 显露前后保持一致 | 时序稳定 |
| 保护车不被抹除 | 目标 A 删净 |

P012、A013／A048 检查保护车；P019 检查新增车；A022／A041 检查删除；P006、M006／M007 和 A061 检查回退。同时增加未用于调参的真实案例。HTML 展示输入、mask、投影条件、r7、新模型，并提供逐帧评分。

**推进条件是：真实 DELETE 中，保护车恢复和无车背景保持两项都出现跨场景收益。**若只在使用隐藏 GT 构建条件时有效，问题仍在状态获取；若简单条件有效而 surfel 无增益，就保留简单版本；若条件已经准确、模型仍忽略它，再针对条件注入与训练目标继续拆解。
