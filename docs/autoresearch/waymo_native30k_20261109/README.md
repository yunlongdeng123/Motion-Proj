# 原生重建续训与质量排查

任务：`WAYMO-NATIVE-RECON-CONTINUE30K-20261109`。

本轮暂停新增编辑实验，先检查原生重建的模糊和残影。两个场景分别从已完成的全帧 10K 检查点精确恢复，延续到 30K；新增正式更新各 20K，学习率时钟沿用原始 30K 计划。scene-065 的 199 帧和 scene-029 的 198 帧全部参加训练，无留出。输入、损失、表示、采样和 seed 均不改变；增加的诊断节点只有 20K、30K 保存与原生渲染。

每个场景先从 10K 完整状态运行至少 600 秒真实 GPU smoke，检查有限损失和梯度、显存、完整检查点、原生渲染、精确状态恢复以及恢复后的两次完整更新。smoke 更新单列，不进入正式续训。正式续训重新从原来的 10K 检查点恢复。

`train_continue30k.py` 沿用现有原生训练入口，仅扩展续训/续训 smoke 的生命周期控制。优化器、随机状态、相机采样器、SGCM、EMA、模型状态均逐项与原检查点比较。仅在精确恢复通过后添加保存节点。`continue_queue.py` 顺序执行并定时记录状态（现按用户要求调整为每 1800 秒），检查子进程错误和时间上限；不调用编辑、不进行电源操作。

CPU 排查核对实际输入轮廓、相机与时间、动态点初始化与运动表示、训练采样和误差。观测支持、已确认工程错误及待验证解释分别记录。不能用流程完成代替质量验收，也不能把参与训练的照片当作独立评价或删除真值。

跨场景边界：065 的既有 10K 使用旧版 480×320 深度网格筛选初始化点，029 使用原始 1920×1280 网格。续训保留各自输入，因此本轮是两个场景各自的步数对照，不是端到端输入协议完全统一的迁移验证。

原始 10K 模型和页面保留。20K/30K 仅使用原生无编辑渲染器输出，并与同帧实拍和 10K 对照。人工结论保持 `null`，等待用户查看。
