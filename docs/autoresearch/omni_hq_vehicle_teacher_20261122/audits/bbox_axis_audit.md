# Omni 包围盒坐标核查

独立源码检查确认，本轮首个候选的包围盒长宽轴与生成车辆语义轴不一致。允许将同一参考、同一 seed 的一次坐标修正重放作为工程接线修复；既有候选与审核结果保留，固定灰模门槛不变。

## 源码证据

源码根目录：`/root/autodl-tmp/third_party/hunyuan3d-omni-v61-me2/`。

| 位置 | 实际行为 |
|---|---|
| `hy3dshape/models/conditioners/omni_encoder.py:407-425` | `bbox_to_corners` 令 `half_dims=bbox/2`，直接逐维乘八组 XYZ 正负号；没有车辆语义旋转。 |
| 同文件 `445-451` | `bbox.repeat(1,1,2)` 直接进入位置编码与线性层，同时调用上述角点函数。 |
| `hy3dshape/pipelines/pipeline_generation_sit_omni.py:146` | 原样传递 bbox 给条件编码器。 |
| 同文件 `291-299` | VAE 解码使用统一空间边界；该段没有 bbox 长宽轴交换或车辆语义对齐。 |

官方注释写 `[length,height,width]`，但可执行路径将三个数直接放在原始 XYZ 空间轴。车辆的语义长度是否落在 raw X，必须由实际输出检查。

## 本候选实际坐标

独立查看 `raw_y_up_four_views.png` 后确认：raw −Z 显示车头引擎盖与格栅；raw +Z 显示货斗盖与尾门；raw +Y 为上。原始纵向长轴因而是 raw Z。此方向判断未使用 LiDAR 或 holdout。

从 raw 到 actor 的旋转为 `[[0,0,-1],[-1,0,0],[0,1,0]]`，行列式 +1；actor 定义为 x 前、y 左、z 上。没有反射或反转面绕序。

首个输入为 raw XYZ `[1,0.416,0.5]`，其角点范围为 X±0.5、Y±0.208、Z±0.25。该输入把最长控制量放在 raw X，而实际车辆长度沿 raw Z。与已知 actor 尺寸 `[5,2.5,2.08]m` 对应的语义控制应为 raw XYZ `[0.5,0.416,1]`。

## 结果解释

首个 raw 的语义 LWH 为 `[1.871414,1.393203,0.806735]`。仅按长度统一初始化为 5m 后得到 `[5.000,3.722,2.155]m`，宽度相对已知尺寸为 1.489。它确实不符合本轮 a20 工程门，但包围盒轴接线错误使该失败不能单独解释为模型表示能力不足。

坐标修正重放必须保留同一 seed101、50步、256解码分辨率、CFG4.5及同一后3/4参考，仅修改输入 bbox 轴排列；不进行 seed、参考、方向或阈值扫描。新输出仍需实际确认语义方向，并重新通过两层灰模审核。
